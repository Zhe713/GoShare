### 2.2 每个服务内部统一分层

```
com.goshare.order
├─ controller     # 只做参数接收/校验/返回，不写业务
├─ service        # 业务编排（事务边界在这一层）
│  └─ impl
├─ domain         # 核心模型：状态机、规则链、库存模型（纯逻辑，可单测）
├─ mapper         # MyBatis-Plus Mapper
├─ entity(DO)     # 表映射
├─ dto            # 入参（带 @Valid 校验）
├─ vo             # 出参（不含敏感字段）
├─ convert        # DO/DTO/VO 转换（手写或 MapStruct）
├─ config         # 本服务配置（Redis/MQ/ES/文档）
└─ job            # XXL-Job 任务
```

**为什么这样分**：`domain` 层是纯 Java 逻辑（状态机、结算规则），可以脱离 Spring 单测——这是你测试体系能做出覆盖率的关键。

### 2.3 goshare-common 放什么（一次写好，全服务复用）

- `Result<T>` 统一返回、`ErrorCode` 枚举、`BusinessException`
- `GlobalExceptionHandler`（参数校验/业务/兜底三类）
- `TraceIdFilter`（MDC 注入，日志与返回都带 traceId）
- `UserContext`（从 JWT 解析出的 userId/角色，ThreadLocal）
- MyBatis-Plus 自动填充（创建/更新时间）、分页插件
- Redis/Redisson 配置、Jackson 序列化统一
- Knife4j 配置基类
- 幂等注解 `@Idempotent`（AOP 实现）

### 2.5 六个关键设计（面试主战场）

**① 座位库存（对应 12306 票池）**
- Redis：`trip:seat:{tripId}` → Hash `{total, remain}`
- 下单 Lua：`if remain>0 then remain-1; return 1 else return 0`（单脚本原子）
- 超时释放：下单发 RocketMQ 延时消息（15 分钟）→ 消费者检查订单状态仍为"待支付"才回补座位（**先查状态再回补，防误释放**）
- 兜底：XXL-Job 每 5 分钟扫描超时未支付订单（防消息丢失）

**② 订单状态机（对应 12306 订单）**
```
待支付 →（支付成功）→ 已占座 →（发车）→ 出行中 →（完成）→ 已完成
   ↓                     ↓
 已取消（超时/主动）      已取消（退款中→已退款）
```
- 迁移守卫：状态表 + 条件更新 `update ... where status = 旧状态`（CAS，天然防并发重复迁移）
- 爽约：出行中未上车 → 完成后标记爽约，影响信任分

**③ 营销券引擎（对应牛券）**
- 三张表：模板（规则）→ 券实例（用户持有）→ 变动日志
- 三类券：满减（门槛+减额）、折扣（折扣率+封顶）、立减（无门槛）
- 叠加规则：`stackable_group` 互斥组（同组只能一张）+ 优先级排序
- 结算责任链：`满减 → 折扣 → 立减`，每步产出中间金额，最终 `payAmount = max(0, amount - discount)`
- 秒杀领取：预热券库存到 Redis → Lua 扣减 → MQ 异步落库发券（去重表幂等）
- 核销/退还：支付成功核销；取消/退款时退还（券回到未用状态，超期则作废）

**④ 幂等（下单/回调/领券三处）**
- 前端生成 `X-Idempotency-Key`；后端 `SETNX` + DB 唯一索引双保险
- 支付回调：以 `payNo` 唯一索引 + 状态机 CAS，重复回调直接返回成功
- 领券：`(template_id,user_id,date)` 唯一索引兜底防超领

**⑤ 消息设计（RocketMQ）**
| Topic | 生产者 | 消费者 | 用途 |
|---|---|---|---|
| order-created | order | marketing/payment | 锁券、创建支付单 |
| order-timeout（延时15m） | order | order | 超时释放座位 |
| trip-full | order | trip/notify | 满员下架、通知 |
| coupon-claim | marketing | marketing | 异步发券（削峰） |
| notify | 各服务 | assistant | 统一通知出口（含天气提醒） |
| trip-changed | trip | trip(索引消费者) | 同步 ES |
- 消费幂等：`t_msg_consume_log(consumer_group, msg_id)` 唯一索引，重复直接 ACK

**⑥ 分库分表 + ES**
- 订单：2 库 × 4 表，分片键 `user_id`（用户查订单天然单库）；券实例同法
- **先单库跑通，阶段 3 再接 ShardingSphere 配置**（避免一开始就被分片问题卡住）
- ES 索引 `goshare_trip`：fromCity/toCity/departTime/price/remainSeats/status，IK 分词；数据由 `trip-changed` 消息同步

### 2.6 网关与可观测
- Gateway：路由（按前缀转发）、全局 JWT 过滤器（白名单放行登录/搜索）、Sentinel 限流规则（秒杀/下单接口 QPS 阈值）、Knife4j 文档聚合
- Skywalking：启动参数挂 agent（`-javaagent`），本地可开关；面试演示链路追踪

### 2.7 AI 助手（assistant-service）怎么做
- **工具层（ToolExecutor）**：6 个方法直调其他服务 Feign（queryTrip/queryOrder/cancelOrder/queryCoupon/claimCoupon/guidePublish/queryWeather）
- **三层漏斗（IntentRouter）**：
  1. 规则层：`t_faq` 表关键词命中 → 直接返回（零 token）
  2. 分类层：意图打分（关键词权重，后续可换小模型）
  3. LLM 层：OpenAI 兼容接口（可切 Ollama），function calling 执行工具
- **Prompt**：system（角色 + 能力边界 + 工具清单）+ 最近 6 轮历史 + 当前消息
- **会话**：`t_conversation` / `t_message` 落库；SSE 推流
- **评估**：`intent-golden.jsonl` 50 条样本 → JUnit 跑准确率 + 工具调用成功率

### 3.4 前端关键实现方式
- **请求层**：axios 实例 + 请求拦截（Bearer token、幂等 Key）+ 响应拦截（统一 code 判断、401 静默刷新、错误提示）
- **鉴权**：双 token（access 2h / refresh 7d），刷新失败跳登录
- **动效**：秒杀按钮三态用状态驱动 class；库存热度条 = 宽度 CSS transition；撕券 = `clip-path` 路径动画；成功弹层 = Vue Transition
- **地图**：高德 JS API 封装两个组件（`MapPicker` 选点、`RouteMap` 画路线）；**先用 mock 坐标跑通**，拿到 key 只替换配置
- **性能**：路由懒加载、行程列表虚拟滚动、图片懒加载、首屏骨架屏
- **大屏**：ECharts + 定时轮询（简单可靠）或 WebSocket 推送
- **联调**：Vite proxy 指向网关 :8000；接口文档直接用 Knife4j

### 3.5 视觉风格：精致设计体系（三主题，玻璃可选）

- 设计体系：两级 design token（基础→语义）+ 三套主题（Glass 玻璃 / Minimal 极简柔和 / Aurora 深色），`data-theme` 一键切换，组件只读 token

- 统一 14 个组件 + 四态 + 列表三态（骨架/空/错误），Storybook 维护全状态
- 工程生态：Stylelint 禁裸样式、Vitest 单测、Playwright 视觉回归、Husky 中文提交、Storybook 文档

## 五、接口规范（全项目统一）

- 路径：`/api/{service}/v1/{resource}`
- 返回：`{code:0, message:"ok", data:{}, traceId:"..."}`
- 错误码分段：`1xxxx` 通用、`2xxxx` 用户、`3xxxx` 行程、`4xxxx` 订单、`5xxxx` 营销、`6xxxx` 支付、`7xxxx` 助手
- 分页：入参 `page/size`，出参 `{list,total,page,size}`
- 鉴权：`Authorization: Bearer <token>`；网关统一校验
- 幂等：关键写接口要求 `X-Idempotency-Key`
- 文档：Knife4j 注解（`@Tag/@Operation/@Schema`），网关聚合可访问

## 九、风险与应对

| 风险 | 应对 |
|---|---|
| 内存不够（ES/MQ/Nacos 同开） | 全项目 512m 分片；Skywalking/Dashboard 默认关；必要时 ES 降 512m |
| ES 8 + IK 插件安装麻烦 | 用 Dockerfile 预装 IK，或先用 ES 自带分词跑通，再换 IK |
| ShardingSphere 与 Boot3 版本兼容 | 阶段 3 才接入，先单库；接入前单独验证 demo |
| 高德 key 未申请 | 地图组件 mock 坐标，配置项替换即可 |
| LLM 不可用/贵 | 三层漏斗让 90% 请求不调 LLM；LLM 可切 Ollama 本地 |
| 微服务拆早了难调试 | 阶段 1-2 本地直连，阶段 3 再接注册中心/网关 |
| 时间不够 | 优先级：核心链路（1-4）> 测试体系（贯穿）> AI（5）> 前端亮点（6）> 文档（7） |
