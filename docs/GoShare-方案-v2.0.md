## 一、项目定位与命名

- 项目名：**GoShare**（中文：顺风拼车平台）；仓库名 `GoShare`
- 一句话：车主发布行程（几个座位），乘客搜路线拼车，下单占座、用优惠券、模拟支付；内置"出行助手"处理搜单/工单/取消挽留。
- 命名原则：**能说人话就不用黑话**——"核销"叫"用券"、"削峰"叫"错峰排队"、"兜底"叫"保底"、"幂等"叫"防重复（幂等）"、"履约"叫"完成行程"。

### 1.1 独立设计声明

本项目与此前的文档校验项目（ai-doc-lint）**完全独立**，不只是 AI 模块：
- 语言与框架完全不同（Java 17 / Spring Boot 3 vs Python / FastAPI），无任何共享代码、依赖或配置
- 数据模型、接口设计、订单状态机、券引擎、分库分表方案均为本项目自行设计
- 测试体系（分层策略、用例设计、WireMock 方案）独立搭建，不沿用旧项目的测试代码
- 前端设计体系（三主题 token、14 组件）为本项目从零建立
- 唯一借鉴的是"求职项目要能演示、要能测试"这一原则，不涉及任何实现复用

## 五、AI 模块新架构（与 ai-doc-lint 彻底划清界线）

### 5.1 界线在哪
旧方案（ai-doc-lint）做的是"从文档里找片段"：本地嵌入 + 重排 + 规则漏斗；致命点是**检索到片段后照样塞进 prompt 再调一次模型，token 一分没省**。
新方案换目标：**同样的问答不重复花钱**。四条机制，不碰向量库、不碰重排、不碰漏斗。

### 5.2 四道关卡（按顺序命中）

| 关卡 | 大白话 | 代码名 | 命中后花多少 token |
|---|---|---|---|
| 第 1 关 | 问过的问题直接答 | `AnswerCache` / `VersionedAnswerCache` | **0**（问题指纹 + 数据版本号精确命中） |
| 第 2 关 | 简单题让便宜模型做 | `SmallModelFirst` | 极少（失败才升级一次） |
| 第 3 关 | 固定开头让厂商帮忙缓存 | `StablePrefixBuilder` | 省掉重复前缀（厂商侧命中） |
| 第 4 关 | 夜里先把常见答案做好 | `AnswerPrecomputeJob` | **0**（读时直接取） |

**两件必须有、但不直接省钱的配套**：
- `LlmGatewayFilter`：统一入口 + 按场景配额 + 超额降档 + 失败降级
- `t_llm_call_log`：每次调用记账（场景/模型/输入输出 token/耗时/是否命中缓存），不然"省了多少"说不清

### 5.3 三套组合（按顺序叠，不是三选一）

| 组合 | 做法 | 预估节省 | 说明 |
|---|---|---|---|
| **甲·省钱流水线** | 指纹缓存 → 小模型（带固定前缀）→ 自检 → 升级一次大模型 → 记账回填 | 约 **74%**（推断） | 零额外容器，全部可 mock |
| **乙·离线先做好** | 夜间批量预生成常见问答（带版本号），读时直接命中 | 覆盖 60% 请求时约 **90%**（推断） | 演示最稳，不怕模型抽风 |
| **丙·统一网关** | 网关上按 A1/B1/A2 配额、降档、降级、记账 | 配合按场景降配再省 **20–40%**（推断） | 把"成本治理"的故事讲圆 |

推荐顺序 **甲 → 乙 → 丙**。数字口径：公开数据可写简历，推断必须自己实测后再写。

### 5.4 三个 AI 功能怎么落到代码

**A1 口语搜行程**
1. `StructuredAsk`：把口语转成 JSON 查询条件（出发地/目的地/时间/是否带大件/是否靠地铁）
2. 查询走 MySQL/ES，排序用规则打分（顺路度、时间接近度、信任分、价格）
3. 模型只输出"推荐理由"一句话
4. 同一句话第二次问 → `VersionedAnswerCache` 命中，0 token

**B1 工单分派 + 摘要 + 草稿**
1. 分派规则文字固定成前缀（`StablePrefixBuilder`），用最便宜的模型分类
2. 摘要：只喂最近 5 条消息 + 标题；长对话先揉成 200 字（`ChatSummaryService`）
3. 草稿：先查模板库，再让模型改写（不凭空生成）
4. 工单数据变了 → 版本号 +1 → 旧缓存自动作废

**A2 取消挽留 + 退改费用解释**
1. `FeeCalculator` 纯 Java 算：已付金额、手续费规则、可退金额、券是否退回
2. 模型只负责把算好的结果说成人话（不碰数字）
3. 挽留话术从预生成池按场景取（改时间/换车/候补），不实时生成
4. 用户确认后才真正执行取消

### 5.5 怎么证明"真的省了"
- 成本 = 输入 token ÷ 1e6 × 输入单价 + 输出 token ÷ 1e6 × 输出单价
- 跑 A/B：100 道真实问题，旧链路 vs 新链路，同时看答案合格率（下降 ≤2 个百分点才算通过）
- 口径纪律：token 一律取响应里的 `usage`，不用估算值

## 八、接口规范

- 路径：`/api/{服务}/v1/{资源}`，资源用复数直白词：`/api/trips/v1/trips`、`/api/orders/v1/orders`

- 分页：`page/size` 入参，`{list,total,page,size}` 出参
- 鉴权：`Authorization: Bearer <token>`
- 防重复：`X-Request-Id`

### 10.2 14 条必写用例（名字就是大白话）

**答案缓存**
1. 同一句话问两次，第二次不叫模型（断言模型调用次数 = 0）
2. 意思相反的两句话不能串答案
3. 价格改了，旧答案立刻作废

**固定前缀**
4. 同一模板两次请求，前缀必须一模一样（否则厂商缓存全废）

**安全**
5. 敏感字段不许进 prompt

**小模型**
6. 小模型答不合格，自动升级一次
7. 升级后仍不合格，走保底话术

**业务正确性**
8. 20 个人抢 10 个座位，不能多卖
9. 重复支付回调 10 次，只记一次账
10. 取消订单，券要退回
11. 满员后，候补第一个自动补位

**网关与体验**
12. 网关超额后降档，不报错
13. 天气提醒按时推送
14. 记账总额与对账结果一致

## 十四、风险与取舍

| 风险 | 应对 |
|---|---|
| 内存吃紧（ES/MQ/Nacos 同开） | 各容器限 512m；Skywalking 可选启；必要时只开核心 4 个 |
| 模型接口不可用 | WireMock 全链路 mock；本地 Ollama 兜底 |
| 缓存把旧数据答出去 | 版本号机制：数据变更即 +1，旧答案自动作废 |
| 模型乱生成业务数据 | A1 列表不生成、A2 金额不算，只用代码出 |
| 微服务过早拆分难调试 | 阶段 1–2 本地直连，阶段 3 才接注册中心 |
| 时间不够 | 优先级：主链路 > 测试体系 > AI 三功能 > 前端亮点 > 文档 |
